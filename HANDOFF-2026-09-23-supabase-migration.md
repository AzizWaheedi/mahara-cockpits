## Constraints & conventions to carry forward

- **Preserve human work.** The root checkout is dirty. Use a new isolated worktree based on fetched `origin/main`; do not reset, auto-stash, overwrite the tracked older `HANDOFF.md`, or delete existing notes.
- **Default dry run.** Every mutating migration/import tool defaults to `DRY_RUN = True`, prints exact impact, tests one row/client first, reads it back, and records a rollback or recovery path. Never fan out from an unverified canary.
- **No unauthorized outward action.** Do not send login emails, Slack/WhatsApp messages or client-visible writes, or trigger provider changes merely to test the migration. Approval for one run is not approval for another.
- **No broad browser privilege.** Service keys stay server-side. Exposed tables need both the correct grants and row policies; every sensitive action verifies the current Auth subject, role and client scope on the server. The CEO email gate is not assignable through an admin role.
- **No continuous Convex mirror.** The old issue-report and checklist shadow settings remain off. A one-time export and final delta under a freeze are migration mechanics, not permission to build another live dual-write system.

- **Current shipping caveat.** `scripts/ship.sh` still deploys Convex. Do not use it unchanged as proof of a Supabase-only production release. Build and verify a replacement release path before the final cutover.
- **Durable record.** Update the cockpit runbook and a new shared-context session note after each verified milestone; distinguish local, preview and production evidence. Do not resurrect the older calendar-based migration plan as a completion claim.

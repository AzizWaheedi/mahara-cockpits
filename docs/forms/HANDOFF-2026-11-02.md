## 6. How to deploy in this repo (the traps cost hours)

- **Git:** never reset, stash or move HEAD in the shared checkout `/Users/abdulazizwaheedi/mahara-cockpits`. Work in
  your own worktree under `~/mahara-worktrees/`, push branches from there, open a PR, merge. Every push to main deploys
  client-success and media-buyer production through Vercel Git, so merge only when the database is ready; still ship
  with `scripts/ship.sh` for the env and bundle check.
- **Disk:** the Mac runs near full. Remove worktrees you created once merged; builders can symlink `node_modules`
  from a base worktree instead of installing. Ask before deleting anything you did not create.
- **Supabase:** only through the CEO's Composio connection (`scripts/dev/forms-deploy/wsql.py`, `mig.py`). Letter rule
  (next free migration letter; check live `schema_migrations`, main and every branch), `guard_check.py`, save
  `before-*.sql`, dry-run the whole chain on live, then apply one by one and read back. A view the VPS sync or CEO
  refresh reads needs every helper function executable by `supabase_read_only_user` (they read through the
  management API's read-only role; `20261101r`).
- **Edge Functions:** `fdeploy.sh <slug> <pushed rev> --dry` then live with `--verify-jwt` equal to the live value.
  Check the function's `updated_at` against branch commit times first: a function can be live from an unmerged branch.
- **Native workers (VPS):** file-scoped hotfix releases from `native-hotfix-release.example.sh`: base check with md5s,
  staged copy, doctors, sync and CEO dry runs, canary under the lock; the release id must be exactly 8 characters; never
  run a canary across 21:00 UTC (midnight Kuwait fails the media publish); a metric value needs its definition under
  the same section; a sync dry run can flag a data-driven table dropping to 0 (compare a regular cycle before blaming
  the release). Start with `setsid nohup ./release-<id>.sh > release-<id>.log 2>&1 < /dev/null &`.
- **csm-calls and client-messages:** their own release folders; stage a read-only `git archive`, doctor and dry run
  from the staged folder, swap the link while holding the run lock, first run detached (`hermes/csm-calls/RUNBOOK.md`,
  `hermes/client-messages/RUNBOOK.md`).
- **Cockpit ships:** `PATH=<a dir with python → Python 3.10+>:$PATH COCKPIT_AUTH_USE_COMPOSIO=1
  VITE_SUPABASE_URL=https://bldgtotkfmhoxmlzowdx.supabase.co VITE_SUPABASE_ANON_KEY=$(cat ~/.cache/mahara-ship/anon.key)
  scripts/ship.sh <app>` from a clean worktree at origin/main (ship's self-test needs Python 3.10+; never add files to
  the worktree while it ships).
- **Portal:** memory `portal-deploy-from-mac`: npm test, tsc, push to portal main, `git archive`, `vercel deploy --prod

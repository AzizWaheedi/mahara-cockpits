## 5. Gotchas

1. **Deploys can wipe the parallel session's work.** `index.ts` is one 5,172-line file and the other session is editing it. Whoever deploys sales-api last wins.
   - Deploy only from the latest main.
   - Always pass `--verify-jwt`. Without it, the service-role door (5138) would accept a forged token.
   - Put new code in new module files plus a one-line registration in `ACTIONS`. The helpers are private, so pass them in or copy them.
2. **Every seat can read `cockpit_sales_settings`.** Never put a Slack signing secret, Zoom keys or Google tokens there.
3. **The keys live on the VPS only.** The Zoom Server-to-Server keys and the Google token are not in sales-api's secrets. The desk's request queue runs every 2 minutes, which is too slow for a live fallback. Moving the keys into function secrets is the CEO's decision.
4. **HighLevel blocks a booking for "now".** `book.create` sends `ignoreFreeSlotValidation: false` (3658), and the calendars need 2 hours' notice (intro) or 1 hour (demo).
   - The demo calendar's location type is Zoom per host, so HighLevel would make a second Zoom link and run its booking automations unless the booking sends `toNotify` false and a custom location.
   - `upcoming()` refuses a second future intro or demo (3607).
5. **`refuseMark` needs the marker's HighLevel user to match the call** (`lib.ts:63-67`). The desk's identity is not a manager and has no HighLevel user, so an automatic "showed" must act as the closer's seat.
6. **The B2B show rule is missing from the calendar status** (see `after_call` in section 3).
7. **A link after a failed call can rarely go on WhatsApp.**
   - The lead has usually not written in 24 hours, so free text is closed, and no template is live. Email is the only route until the CEO creates templates.
   - Template sends are also limited: no second template to the same lead within 2 minutes (1168), and 250 a day (1177).
   - The WA Connector duplicates every send on the number until it is switched off.
8. **Timing:**
   - The intro comes back to the queue after `INTRO_RETRY` (5 minutes), but the lead wait is 10 minutes.
   - The queue's slow half is cached for 20 seconds (`HEAVY_FOR` 2346), so new state can take that long to show.
9. **Zoom and Meet limits:**
   - Basic Zoom users are cut at 40 minutes, and demos run 45 (https://support.zoom.us/hc/en-us/articles/5809097508109-May-2-2022-Free-account-meeting-duration-changes).
   - The setter's Zoom seat is pending. UNVERIFIED: whether a meeting can be created for a pending user.
   - A Meet link made through Calendar lets outsiders in without knocking only when the access type is `OPEN`, which needs the Meet API (https://developers.google.com/workspace/meet/api/reference/rest/v2/spaces). Without that API there is no join detection for Meet.
10. **Slack is not ready for P2.** The setter and the closer are not in Slack, no seat has a `slack_user_id`, and the existing bot belongs to the assistant. UNVERIFIED: whether that bot's single Interactivity URL is already in use.
11. **The lapsed sign-in is hidden on the follow-ups status row.** The followups row reads ok (18:37) while notes, reviews and digest fail with the sign-in sentence. The agent only meets the lapse when it tries to draft. The `followups.py` docstring still says "OpenAI"; the provider is now `vps` (`model.py:50`).
12. **Database constraints refuse new values.**
    - `cockpit_sales_messages.source` allows only `rep` and `followup`.
    - `cockpit_sales_requests.kind` has a fixed list.
    - `cockpit_sales_people.role` allows only setter, closer, both and manager.
13. **Test data.** Use only the test contact `VjPfR4Cc1Y0OFvaqeor5`. The harness and the desk tests never reach the network.
14. **Calendar data is thin right now.** The calendar copy shows only 2 calls in the last 8 days (latest start 2026-09-30). Live testing will have little data to work with.

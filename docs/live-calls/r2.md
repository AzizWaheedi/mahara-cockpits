## Zoom

- Creating a meeting is `POST /users/{userId}/meetings`. `userId` can be a user ID or an email. Scopes are `meeting:write:admin` or the granular `meeting:write:meeting:admin`. The rate limit label is LIGHT. Each host user gets 100 create or update requests per day, reset at 00:00 UTC. https://developers.zoom.us/docs/api/meetings/ (section "Create a meeting"). VERIFIED
- Meeting `type` values: 1 instant, 2 scheduled (the default), 3 recurring with no fixed time, 8 recurring with a fixed time, 10 screen share only. Same page. VERIFIED
- If `start_time` is missing or in the past, it defaults to the current time. So a type 2 meeting can start "now". Same page. VERIFIED
- `join_before_host` defaults to false and is only used for types 2, 3 and 8, so type 1 ignores it. Turning `waiting_room` on disables `join_before_host`. `jbh_time` takes 0, 5, 10 or 15. Same page. VERIFIED
- `waiting_room_options.mode` "custom" with `who_goes_to_waiting_room` takes: everyone, users_not_in_account, users_not_in_account_or_whitelisted_domains, users_not_on_invite, users_not_in_org. Same page. VERIFIED
- `default_password` (true by default) generates a passcode when the user's "Require a passcode" setting is on. The 201 response returns `join_url`, `password`, `encrypted_password`, `h323_password` and `start_url`. Same page. VERIFIED
- `start_url` expires after two hours for regular users. Anyone holding it can start the meeting as host, so it must reach only the host. Same page. VERIFIED
- Embedding the passcode in the join link is the account setting "Embed passcode in invite link for one-click join". I did not open the official Zoom article. https://webmeetings.unm.edu/advanced-topics/one-click-join.html UNVERIFIED
- Basic (free) users on free and paid accounts are limited to 40 minutes when there is 1 host with 1 or more participants, or no host with 1 or more participants. A meeting started without the host still follows the host's limit. Basic users on Pro, Business or Enterprise accounts get the free durations. Licensed users get 30 hours. A licensed meeting ends 40 minutes after only one person is left. https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0067966 VERIFIED
- Basic users, and licensed users on a Pro account, can host 1 meeting at a time, "regardless of if he is actually present in the meeting or not". Licensed users on Business, Education or Enterprise accounts can host 2. When the host is at the limit, people joining a meeting that has not started see that the host has another meeting in progress. https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0068522 VERIFIED
- An alternative host must be Licensed, and both users must be on the same account. The meeting still follows the original host's limits. https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0067027 VERIFIED
- Server-to-Server OAuth: get the token from `https://zoom.us/oauth/token` with `grant_type=account_credentials`. It expires in 3,600 seconds. There is no refresh token, and several tokens can be valid at once. https://developers.zoom.us/docs/internal-apps/s2s-oauth/ VERIFIED
- Server-to-Server OAuth apps can turn on event subscriptions in the app's Feature step. https://developers.zoom.us/docs/internal-apps/create/ VERIFIED
- Endpoint URL validation: Zoom sends `endpoint.url_validation` with `payload.plainToken`. Within 3 seconds, reply 200 or 204 with `{plainToken, encryptedToken}`. `encryptedToken` is the HMAC SHA-256 of `plainToken`, keyed with the webhook secret token. Zoom revalidates the URL every 72 hours. https://developers.zoom.us/docs/api/webhooks/ VERIFIED
- Signature check: build `v0:{x-zm-request-timestamp}:{raw body}`, take the HMAC SHA-256 with the secret token, prefix `v0=`, and compare with `x-zm-signature`. Same page. VERIFIED. That the digest is hex: UNVERIFIED. The page I opened states no timestamp window for replay protection.
- Delivery: reply 200 or 204 within 3 seconds. On a 500 or higher, Zoom retries 3 times, at 5, 20 and 60 minutes. Duplicate events can occur across subscriptions. The page states no ordering guarantee. Same page. VERIFIED
- Available meeting events include: meeting.started, meeting.ended, participant_joined, participant_left, participant_joined_waiting_room, participant_left_waiting_room, participant_admitted, participant_put_in_waiting_room, participant_jbh_waiting, participant_jbh_joined and participant_role_changed. https://developers.zoom.us/docs/api/meetings/events/ VERIFIED
- These events fire only when the meeting host is a user in your account, or in an account that installed the app. Same page. VERIFIED
- `participant_jbh_waiting` fires after a guest has waited 30 seconds for the host on native clients, and immediately on web clients. Same page. VERIFIED
- `participant_joined` payload fields:
  - `object.host_id`: the host's user ID.
  - `participant.user_id`: valid only for that meeting.
  - `participant_user_id`: the account user ID if the person signed in to Zoom; empty if they did not sign in or are external.
  - `email`: empty when the participant is not in the host's account (with some exceptions).
  - Also `user_name`, `join_time`, `participant_uuid` and `phone_number`.
  
  Same page. VERIFIED
- From those fields: the host is the participant whose `participant_user_id` equals `host_id`. Staff who sign in show their own ID and email. A lead shows neither, so the lead is "the participant who is not staff". The fields are VERIFIED; this rule is my inference.
- `participant_left.leave_reason` values include "Host did not join.", "Exceeded free meeting minutes limit." and "Leave waiting room.". Same page. VERIFIED
- API rate limits: Pro allows Light 30/s, Medium 20/s, Heavy 10/s. Business and above allow 80/s, 60/s and 40/s. Free accounts also have daily caps. https://developers.zoom.us/docs/api/rate-limits/ VERIFIED
- Instant meeting IDs expire when the meeting ends. Scheduled meeting IDs expire 30 days after the scheduled date or the last use. https://answers.illinois.edu/118079 UNVERIFIED
- Joining from a browser depends on the "Show a Join from your browser link" setting. Mobile browsers get fewer features. https://support.zoom.us/hc/en-us/articles/115005666383 UNVERIFIED
- Creating meetings for a user whose invite is still pending fails. UNVERIFIED (not tested)

## Google Calendar and Meet

- `events.insert` with `conferenceData.createRequest` needs the query parameter `conferenceDataVersion=1`. The default, 0, ignores conference data. `sendUpdates` takes all, externalOnly or none. Scopes are calendar, calendar.events, calendar.app.created or calendar.events.owned. https://developers.google.com/workspace/calendar/api/v3/reference/events/insert VERIFIED
- The conference is created asynchronously. `createRequest.status.statusCode` is pending, success or failure. On success, Google fills `entryPoints[].uri` and the read-only `hangoutLink`. The conference type is `hangoutsMeet`. https://developers.google.com/workspace/calendar/api/guides/create-events and https://developers.google.com/workspace/calendar/api/v3/reference/events VERIFIED
- About `requestId`, the reference says: "Clients should regenerate this ID for every new request. If an ID provided is the same as for the previous request, the request is ignored." It deduplicates the conference request, not the event. For an idempotent event, supply your own event `id`: base32hex characters a to v and 0 to 9, 5 to 1,024 characters, unique per calendar. Google warns that collisions may not be detected at creation time. Same reference page. VERIFIED
- `guestsCanInviteOthers` defaults to true. Same reference page. VERIFIED
- Each calendar lists the conference types it allows in `conferenceProperties.allowedConferenceSolutionTypes`. Secondary calendars carry `dataOwner`. https://developers.google.com/workspace/calendar/api/v3/reference/calendars VERIFIED. Whether a secondary calendar allows Meet, and who becomes host there: UNVERIFIED.
- Calendar API quota: 10,000 requests per minute per project and 600 per user per project. Unpublished "operational limits" also apply. https://developers.google.com/workspace/calendar/api/guides/quota VERIFIED
- Access types and who joins without knocking:
  - Open: anyone with the link.
  - Trusted: anyone in the host's organisation with the link, plus external guests invited through the Calendar event.
  - Restricted: only Calendar invitees and people a host invites from inside the meeting.
  
  External invitees skip the knock only "if signed in to a Google Account". Each meeting also has a "Host must join before anyone else" On/Off setting. https://support.google.com/a/users/answer/12172260 VERIFIED
- New meetings default to Trusted, and guests can join before the host. Open, Trusted and Restricted replaced Quick access, rolling out from 2023-07-17. https://workspaceupdates.googleblog.com/2023/06/simplified-access-controls-for-google-meet.html VERIFIED
- Host management table: when it is on, only hosts and co-hosts can accept knocks. When it is off, any internal participant can accept knocks. Your Google admin sets the default. https://support.google.com/a/users/answer/12172260 VERIFIED. In the Calendar video call options it is "off by default". https://support.google.com/meet/answer/16229038 VERIFIED
- Someone without a Google account can join, "but the organizer or a participant needs to let you in". https://support.google.com/meet/answer/9303069 VERIFIED
- A conflicting passage on the bulk-admit help page says: "Only the meeting organizer can find or approve requests to join a meeting." https://support.google.com/meet/answer/9303164 VERIFIED
- Co-hosts and waiting rooms need Business Standard or Plus. All Business editions allow 24-hour meetings, with 100, 150 or 500 participants. https://knowledge.workspace.google.com/admin/meet/compare-meet-features-across-google-workspace-editions VERIFIED. Mahara's edition: UNVERIFIED.
- Personal accounts: 1:1 meetings up to 24 hours; meetings with 3 or more people up to 60 minutes. Phones need the Meet app, the Gmail app or a supported browser; iPhones need iOS 17 or later. https://support.google.com/meet/answer/7317473 VERIFIED. Whether mobile browsers fully work: UNVERIFIED.
- Meet REST API `spaces.create` is `POST https://meet.googleapis.com/v2/spaces` with scope `meetings.space.created`. `accessType` OPEN means "Anyone with the join information ... can join without knocking". https://developers.google.com/workspace/meet/api/reference/rest/v2/spaces/create and https://developers.google.com/workspace/meet/api/reference/rest/v2/spaces VERIFIED
- Meet REST API scopes:
  - `meetings.space.created`: Sensitive; only covers spaces your app created.
  - `meetings.space.readonly`: Sensitive; reads any space the user can access.
  - `meetings.space.settings`: Non-sensitive; "Edit and see the settings for all of your Google Meet calls".
  
  https://developers.google.com/workspace/meet/api/guides/authenticate-authorize VERIFIED
- `spaces.get` accepts `spaces/{meetingCode}`. `spaces.patch` accepts `meetings.space.created` or `meetings.space.settings`. https://developers.google.com/workspace/meet/api/reference/rest/v2/spaces/get and https://developers.google.com/workspace/meet/api/reference/rest/v2/spaces/patch VERIFIED. That `patch` can switch a meeting made through Calendar to OPEN: UNVERIFIED.
- `conferenceRecords.participants.list` with `filter=latest_end_time IS NULL` returns the people currently in the call. Scopes are created or readonly. Participant records:
  - `signedinUser`: `users/{id}`, no email.
  - `anonymousUser`: display name only.
  - `phoneUser`: partly redacted number.
  
  https://developers.google.com/workspace/meet/api/reference/rest/v2/conferenceRecords.participants/list and https://developers.google.com/workspace/meet/api/reference/rest/v2/conferenceRecords.participants VERIFIED
- Workspace Events API: `google.workspace.meet.participant.v2.joined` and `left`, and conference started and ended. A subscription targets one space, or one user (all spaces that user owns). Calendar invitees only receive conference.started and transcript fileGenerated. https://developers.google.com/workspace/events/guides/events-meet VERIFIED
- An Internal OAuth app (project owned by the organisation, consent screen set to Internal) skips the unverified-app screen and the 100-user cap. https://support.google.com/cloud/answer/13464323 VERIFIED

## Slack

- Request signing: build `v0:{X-Slack-Request-Timestamp}:{raw body}`, take the HMAC SHA-256 with the signing secret, hex-encode it, prefix `v0=`, and compare with `X-Slack-Signature`. Reject timestamps more than 5 minutes from local time. Verification tokens are deprecated. https://docs.slack.dev/authentication/verifying-requests-from-slack VERIFIED
- Interactivity payloads arrive form-encoded with a `payload` JSON field. Reply HTTP 200 within 3 seconds. `response_url` can be used up to 5 times within 30 minutes, with `replace_original` or `delete_original`. https://docs.slack.dev/interactivity/handling-user-interaction VERIFIED
- App manifest:
  - `settings.interactivity`: `is_enabled`, a single `request_url`, and `message_menu_options_url`.
  - `settings.socket_mode_enabled`.
  - `settings.event_subscriptions.request_url`.
  - `features.slash_commands`: up to 50 commands, each with a name up to 32 characters, an optional `url`, a description and `should_escape`.
  - `features.app_home`: `home_tab_enabled`, `messages_tab_enabled`, `messages_tab_read_only_enabled`.
  - Up to 255 bot scopes.
  
  https://docs.slack.dev/reference/app-manifest VERIFIED
- Socket Mode replaces public request URLs with a WebSocket. It needs an app-level token with `connections:write`, a call to `apps.connections.open`, and an acknowledgement for every `envelope_id`. Up to 10 connections; connections refresh, so the app must reconnect. Socket Mode apps cannot go in the public Marketplace. https://docs.slack.dev/apis/events-api/using-socket-mode VERIFIED
- `chat.update` needs `chat:write`, `channel` and `ts`. It is Tier 3. It only edits messages posted by the same token and cannot edit ephemeral messages. https://docs.slack.dev/reference/methods/chat.update VERIFIED
- `users.lookupByEmail` needs `users:read.email` and is Tier 3. It returns `users_not_found` for deactivated users. https://docs.slack.dev/reference/methods/users.lookupByEmail VERIFIED

## Facts that change the design

1. **The closer's Basic Zoom licence ends a 45-minute demo at 40 minutes.** The cut applies when the lead is alone with the closer and when the closer is not present. A licensed person joining does not lift it, and an alternative host must be licensed too. This decides open decision 1: the closer needs a licence, or demos move to Meet. Intros (15 minutes) are fine on Basic.
2. **Each Zoom host can run one meeting at a time (Basic, or licensed on Pro), even when absent.** A closer in a demo cannot open a live room. The availability check must ask Zoom whether the closer's meeting is running, not only read the Slack button. A Business account allows 2. Hosting every room on the CEO's licensed user would hit the same limit.
3. **Use a type 2 meeting with no `start_time`, so it starts now.** Set `waiting_room: true` with mode custom and `users_not_in_account`, so staff walk in and the lead waits. Type 1 ignores `join_before_host`, and a waiting room disables it anyway. Someone with host or co-host rights must admit the lead. That is UNVERIFIED for Zoom, because I did not open Zoom's waiting-room article.
4. **Zoom tells you which participant is staff, not which one is the lead.** Signed-in staff show their account ID and email; the lead shows neither. "Lead joined" means "a non-staff participant joined", with the display name as a hint. Retries arrive 5, 20 and 60 minutes late, so a missed event is not a reliable shown mark.
5. **Meet booked on the CEO's calendar makes the CEO the host.** Keep host management off and "Host must join before anyone else" off, or nobody can admit the lead. With host management off, any internal participant (the setter or the closer signed in to maharamedia.com) can accept the knock. A lead with no Google account, or not signed in as the invited email, always knocks. One Google page says only the organiser approves knocks, so test this with the test contact before launch.
6. **Meet gives no join signal with the current token.** "Lead joined" detection, and with it decision 2 (book and mark shown when the lead joins), needs one of these:
   - `meetings.space.readonly` plus the participants list.
   - The Workspace Events subscription for the CEO's user.
   - `meetings.space.created` for OPEN spaces.
   
   Without one, a rep marks Meet calls by hand. `meetings.space.settings` (Non-sensitive) might switch an existing Calendar meeting to OPEN through `spaces.patch` (UNVERIFIED). An Internal consent screen avoids Google verification.
7. **The current booking call refuses a live intro.** sales-api sends `ignoreFreeSlotValidation: false` and `ignoreDateRange: false`, so the intro calendars' 2 hours' notice blocks "now". The live path needs `ignoreFreeSlotValidation: true`.
   - On the demo calendar, also send `meetingLocationType: "custom"`, `address` set to our join link and `overrideLocationConfig: true`. Otherwise HighLevel's per-host Zoom location may create a second room; that is my inference from the field docs.
   - Set `toNotify: false` on the create so HighLevel does not send "your call is booked" reminders mid-call.
   - `appointmentStatus` accepts "showed", so the booking and the shown mark can be written together.
8. **Slack and Zoom cannot call sales-api directly, because it runs verify_jwt.** Put a new Edge Function with `verify_jwt = false` in front. It checks the Slack and Zoom signatures, answers within 3 seconds, and does the Zoom and HighLevel work after the acknowledgement, via `chat.update` or `response_url`.
9. **Build a separate Slack app for sales.** One app has one interactivity URL, and the existing bot belongs to the AI assistant. An HTTP request URL avoids Socket Mode's dependency on the VPS.
10. **The setter and the closer must join Slack before "I'm available in Slack" can work.** Today neither is in the workspace and no seat has a `slack_user_id`, so a cockpit button should do the same job.
11. **Route A (official WhatsApp group) needs more than an OBA.**
    - There is no add-participant call: the lead must tap an invite link sent with a utility template.
    - The number must be on Cloud API, not the WhatsApp Business app.
    - The app calling the Groups API must be subscribed to the WhatsApp Business account. That app is HighLevel's, and I found no HighLevel groups feature.
    - Adding a second integration risks Multi-solution Conversations, where groups are excluded.
    - If the WA Connector means the number is shared with the WhatsApp Business app, groups are off entirely (UNVERIFIED).
    - Buttons do not work inside groups.
    
    This supports route C now.
12. **If route A ever runs:** `DELETE /<GROUP_ID>` covers decision 4 (ending the group), and a removed person cannot rejoin by link. Each billable template is charged once per member, so three members cost three times. Any member's message opens a free window for the whole group.
13. **A handover that starts because the lead replied needs no template.** The 24-hour window is open, and free text with the link costs nothing. Only the Maqsam fallback outside the window needs a template.
14. **The fallback link must fit a fixed-base URL button, so use a short link.** Zoom links carry a host subdomain and `?pwd=`, which do not fit cleanly. `https://call.maharamedia.com/{{1}}` (one GoDaddy CNAME) or `https://meet.google.com/{{1}}` does.

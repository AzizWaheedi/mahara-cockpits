# Quick pitch and client preparation

## Design plan, 27 October 2026

Audience: a CSM about to explain one service during a client conversation. One job: open a strong presentation immediately, or prepare the specific client version without hunting through settings.

Direction: a working shelf of seven service instruments. Each cover and scope illustration belongs to its service: website window, parallel campaign branches, indexed search dossier, publishing contact sheet, camera storyboard, real presenter reels and recruitment timeline. Avoid seven identical icon buttons or seven variations of one property photograph.

Tokens: retain Deep Space #091333, card #0f1b45, Mahara Teal #00cfc8, white #f2f6fa, muted blue #506179 and existing warning token. Geist display/body, Geist Mono only true utility/counts, IBM Plex Sans Arabic for Arabic. All CSS uses existing cockpit/deck tokens. No new brand palette.

Layout: deck shelf → Quick pitch; client picker → Quick pitch or Prepare for client; preparation → essential inputs first, optional personalization folded. The generic deck has chapter controls and English/Arabic switching. A persistent private strip explains that examples carry no client record or quote.

Signature: the offer's working object appears on its shelf cover and is enlarged in the presentation. It is useful evidence of the service's shape, not decoration or a fabricated result.

## Safety and content

Quick pitch reuses the client-free catalog model. No fake client ID is passed to PresentApp, no prep saver/hub/telemetry/pitch/proposal/outcome mutation. It never changes server eligibility. Hide client diagnosis and omit investment by default. Keep the approved clean close. A private toggle may show actual catalog list pricing when complete, except Closer, whose pricing remains in client preparation; no client quote is inferred. Only approved catalog copy and existing bilingual labels appear on the shared canvas. Company-folder names describe supplied example provenance, never actor identities.

Missing personalized photos use the bundled fictional architecture with the existing approved Example label, never empty media tiles or claimed client work. Captures/goals/prices are not invented. The normal client preparation keeps current pricing, logged below-list reason, recruiter and server send/present safeguards.

Not in scope: frozen release 85a87, film source/audio, SQL/Edge changes, production or provider writes, new Arabic claims, new assets/packages/downloads, or unrelated cockpit navigation.

How we know it works: named unit tests for all 7 generic offers, zero mutation paths, missing catalog/retry/scope races, exact client prep links and explicit fallbacks. After host clearance, browser fixture QA at 390/820/1440 for entry UI, EN/AR deck stops at 1366/1920, clear images/brand, safe bounds and real navigation. Keep ordinary client recording/proposal regression checks unchanged. Results are recorded only after running.
